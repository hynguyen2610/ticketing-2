System Architecture

Ticketing Platform

A Node.js microservice system running on Kubernetes. The client uses Next.js as the public entry point, backend services own their data, and state changes are coordinated through NATS Streaming events.

Flows

Primary Request and Event Paths

Auth0 Login

  1. Browser opens /auth/login through the client.
  2. Next.js rewrites the request to auth-srv.
  3. The auth service redirects to Auth0 and receives /auth/callback.
  4. Auth issues the existing internal session cookie signed with JWT_KEY.
  5. Backend services continue to trust the internal JWT, not raw Auth0 tokens.

Create and Reserve Ticket

  1. Authenticated user creates a ticket through the client.
  2. Tickets service stores the listing and publishes ticket events.
  3. Buyer creates an order from a ticket.
  4. Orders service reserves the ticket and publishes order:created.
  5. Expiration and payment services receive their order replicas from the event stream.

Payment

  1. Client loads Stripe Checkout with NEXT_PUBLIC_STRIPE_PUB_KEY.
  2. Stripe returns a one-time token to the browser.
  3. Client posts token and order id to /api/payment.
  4. Payment service validates the order replica and charges Stripe with STRIPE_KEY.
  5. Payment service publishes payment:created; orders marks the order complete.

Expiration

  1. Expiration service receives order:created.
  2. A delayed Redis-backed job is scheduled until the order deadline.
  3. When the job runs, expiration publishes expiration:complete.
  4. Orders cancels unpaid reservations and publishes order:cancelled.
  5. Tickets and payment services update their replicas from cancellation events.

Operations

Local Development and Secret Notes

Development Loop

  • Tilt is the preferred local workflow.
  • The client is commonly forwarded to localhost:13100.
  • Playwright validates client UI routes across desktop, tablet, and mobile.

Required Secrets

  • jwt-secret with JWT_KEY.
  • stripe-secret with matching STRIPE_KEY and NEXT_PUBLIC_STRIPE_PUB_KEY.
  • auth0-secret-ticketing when Auth0 login is enabled.

Stripe Key Rule

  • The publishable key creates browser tokens.
  • The secret key charges those tokens on the server.
  • Both keys must come from the same Stripe account and mode.
